# TripDocket privacy policy

In the app, open **Settings → Privacy & support** (Russian: **Настройки → Данные
и помощь**) for bundled guidance available offline and without Pro. It describes
local storage, deletion, temporary copies, unencrypted exports, recovery and
Apple services. Web buttons show the public destination before the user chooses
to open it. No document data is appended to those URLs.

Expanded privacy drafts: [English](app-store/drafts/privacy-en-US.md) · [Russian](app-store/drafts/privacy-ru.md).
These drafts still need real owner/contact details before App Store submission.

Effective for the development preview, 20 October 2026.

TripDocket processes imported/scanned documents and OCR on the device. There is
no mandatory TripDocket account, developer-operated document server, advertising
SDK, analytics SDK or crash-upload SDK in this application. No document contents
are sent to the developer by the app.

Apple operates the App Store, device authentication and optional system backup.
Purchases use StoreKit. The app reads verified purchase entitlement and localized
product information; it does not receive payment-card details. Apple processes
these services according to its own terms and privacy policy.

Camera access is used only for scanning after the user requests it. Files access
is limited to selections made through Apple's picker. Notification permission is
requested only when the user schedules a reminder. Notification text avoids
document titles, names and identifiers.

Batch-import preparation keeps selected originals in bounded memory until the
user confirms and saves the batch. The unsaved draft is not persisted and is
lost when the process exits. Preview copies use protected temporary cache files.

Documents are kept in the local sandbox with complete file protection. Device
backup behavior follows Apple settings. Exported files and portable backup
packets are plaintext; a user-selected destination or recipient can read them.
Deletion in the app cannot delete copies previously exported elsewhere.

Public support issues are visible to everyone. Do not attach sensitive content.
Use synthetic examples and private vulnerability reporting for security issues.
The repository support pages identify the available contact routes.
